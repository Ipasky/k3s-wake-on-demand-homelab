# 3 · K3s

[← 2 · Firewall](02-firewall.md) · [Guide index](README.md) · Next: [4 · Power →](04-power.md)

The Pi runs the K3s **server**; each PC joins as an **agent**. The nodes get labels that describe
them and a **taint** that keeps everything off them except work that explicitly asks for a sleeping
node.

## 3.1 Server on the Pi

```bash
curl -sfL https://get.k3s.io | sh -s - --write-kubeconfig-mode=644
sudo k3s kubectl get nodes          # pi-master  Ready  control-plane
```
K3s brings Traefik (ingress), a service load balancer and local-path storage; this cluster uses all
three.

Note the exact version, the agents must use the same one:
```bash
k3s --version                       # e.g. v1.36.4+k3s1
sudo cat /var/lib/rancher/k3s/server/node-token
```

Keep your manifests in a folder of the normal user, so they end up in the configuration backups
(chapter 12):
```bash
mkdir -p ~/k8s && sudo ln -s /home/raspberrypi/k8s /root/k8s
echo 'export KUBECONFIG=/etc/rancher/k3s/k3s.yaml' >> ~/.bashrc
```

## 3.2 Agents on the nodes

On each node, **with the server's version**: without `INSTALL_K3S_VERSION` the script installs the
latest one, and an agent newer than the server is not supported:

```bash
curl -sfL https://get.k3s.io | INSTALL_K3S_VERSION=v1.36.4+k3s1 \
  K3S_URL=https://192.168.1.20:6443 K3S_TOKEN=<node-token> sh -
```

## 3.3 Labels and taint

From the Pi:
```bash
kubectl label node pi-master power-mode=always

kubectl label node faraday node-type=cpu power-mode=ondemand
kubectl label node mustang node-type=gpu power-mode=ondemand
kubectl taint node faraday power=ondemand:NoExecute
kubectl taint node mustang power=ondemand:NoExecute

kubectl get nodes -L power-mode,node-type
```
- `node-type` is how a job asks for a CPU or a GPU node.
- The **taint** keeps every ordinary pod on the Pi. `NoExecute` also evicts anything that lands on a
  node by mistake; otherwise a stray pod would keep a node awake forever.

## 3.4 GPU support (NVIDIA node only)

On the GPU node:
```bash
sudo ubuntu-drivers install && sudo reboot
nvidia-smi                                         # the card and the driver version

curl -fsSL https://nvidia.github.io/libnvidia-container/gpgkey | \
  sudo gpg --dearmor -o /usr/share/keyrings/nvidia-container-toolkit-keyring.gpg
curl -s -L https://nvidia.github.io/libnvidia-container/stable/deb/nvidia-container-toolkit.list | \
  sed 's#deb https://#deb [signed-by=/usr/share/keyrings/nvidia-container-toolkit-keyring.gpg] https://#g' | \
  sudo tee /etc/apt/sources.list.d/nvidia-container-toolkit.list
sudo apt update && sudo apt install -y nvidia-container-toolkit
sudo systemctl restart k3s-agent                   # K3s detects the NVIDIA runtime on start
```
On the Pi, once:
```bash
kubectl apply -f - <<'YAML'
apiVersion: node.k8s.io/v1
kind: RuntimeClass
metadata:
  name: nvidia
handler: nvidia
YAML
```

Quick test (the node must be awake; a bare `kubectl run` pod does not wake nodes, only jobs do):
```bash
kubectl run gpu-test --rm -it --restart=Never --image=nvidia/cuda:12.4.1-base-ubuntu22.04 \
  --overrides='{"spec":{"runtimeClassName":"nvidia","nodeSelector":{"node-type":"gpu"},"tolerations":[{"key":"power","operator":"Exists"}]}}' \
  -- nvidia-smi
```

## 3.5 kubectl from the admin PC

```powershell
winget install -e --id Kubernetes.kubectl
mkdir $env:USERPROFILE\.kube -Force
scp pi:/etc/rancher/k3s/k3s.yaml $env:USERPROFILE\.kube\config
(Get-Content $env:USERPROFILE\.kube\config) -replace '127.0.0.1','192.168.1.20' | Set-Content $env:USERPROFILE\.kube\config
kubectl get nodes
```
The kubeconfig is **root on every node**: treat it like a password.

## 3.6 The job template

Work for a sleeping node is a **Job** (not a bare pod) that selects the node type and tolerates the
taint. The power controller of the next chapter wakes the node when such a job is pending:

```yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: my-render
spec:
  backoffLimit: 0
  ttlSecondsAfterFinished: 3600
  template:
    spec:
      restartPolicy: Never
      runtimeClassName: nvidia          # only for GPU work
      nodeSelector:
        node-type: gpu                  # or cpu
      tolerations:
        - key: power
          operator: Equal
          value: ondemand
          effect: NoExecute
      containers:
        - name: work
          image: your/image
```

> Volumes on the nodes: the local-path provisioner cannot create its helper pods on tainted nodes,
> so declare them as `hostPath` (or a manual local PersistentVolume).

## 3.7 Upgrading later

Always **the server first**, then each agent with the same `INSTALL_K3S_VERSION`, and back up the
server database before:
```bash
sudo systemctl stop k3s && sudo cp -a /var/lib/rancher/k3s/server/db /root/k3s-db-$(date +%F) && sudo systemctl start k3s
curl -sfL https://get.k3s.io | INSTALL_K3S_VERSION=vX.Y.Z+k3s1 sh -s - --write-kubeconfig-mode=644
```
Keep a node awake while you upgrade it: `kubectl label node faraday power-hold=true` (remove the
label with `power-hold-` when done).
